# Проверка BeeGarden — 25.11.2026

Проверены клиент, Express API, зависимости, действующая схема Supabase и настройки
сервиса BeeGarden в Render. Это проверка кода и конкретных сценариев, а не гарантия
отсутствия любых уязвимостей и ошибок.

## Исправлено

| Проблема | Изменение |
| --- | --- |
| Критическая: API доверял переданному `user_id`, выполняя запросы service-role ключом | Проверка Supabase access token, запрет несовпадающего владельца, отдельный клиент с JWT пользователя и RLS |
| Push endpoint мог указывать на произвольный внутренний адрес | HTTPS и список браузерных push-провайдеров, проверка ключей подписки, повторная проверка адреса перед отправкой |
| Отсутствовали ограничения запросов и защита внешних вызовов | Rate limiting, предел JSON 32 КБ, запрет сжатых тел, таймауты Supabase/погоды/push, безопасные ошибки |
| Широкий CORS и отсутствие защитных заголовков | Список разрешённых origins, Helmet на API, CSP и другие заголовки Netlify |
| У `hives` отсутствовали RLS-политики; дубли и построчные проверки в других таблицах | Политики только для владельца на 9 таблицах, вычисление `auth.uid()` через InitPlan, запрет анонимного доступа и записи истории из браузера |
| Недостающий индекс FK и сортировок | Индексы владельца карточки, списка ульев, ожидающих напоминаний, дат откачки |
| Данные можно записывать напрямую из браузера в обход API-валидации | Ограничения БД на роения, длину заметок/задач, положительный конечный объём мёда |
| Уязвимые зависимости | Обновлены lock-файлы; `npm audit` не сообщает известных уязвимостей в обоих пакетах |
| В Git хранились установленные зависимости сервера | `server/node_modules` удалён из индекса Git; установка воспроизводится по lock-файлу |
| Лишний JavaScript при открытии входа | Интерфейс авторизованного пользователя и Axios загружаются по необходимости |
| Частые одинаковые запросы погоды и push-синхронизации | Ограниченный кэш погоды на 5 минут, объединение одновременных запросов, защита повторной синхронизации |
| Погодный провайдер отклонял запросы с Render при успешном ответе браузеру | Резервный запрос из браузера с таймаутом, отменой и без передачи токена; ошибки авторизации не запускают fallback; сохранение локации больше не зависит от доступности погоды |
| N+1 запросов подписок планировщика, зависание блокировки после исключения | Один запрос подписок на пакет; освобождение блокировки в `finally`, обработка фоновых ошибок |
| Ошибки интерфейса | Обработка сбоев входа и загрузки сессии, подписи полей входа, нулевые координаты, ограничение переходов push своим origin, исправление z-index календаря, изоляция состояния при смене пользователя, удаление подписки и пользовательского кэша при выходе |

## Проверки и измерения

- 12 автоматических серверных тестов: авторизация, подмена пользователя,
  изоляция запросов, входные данные, SSRF, лимиты, кэш погоды, cron и планировщик.
- ESLint и production-сборка клиента проходят.
- 5 клиентских тестов проверяют резервную загрузку погоды и отмену запросов.
- Реальный вход через Supabase; чтение ульев и карточки через обновлённый локальный
  API вернуло 200, подмена пользователя — 403. Пользовательские записи не изменялись.
- Проверка БД в транзакции с последующим rollback: владелец видит свои ульи;
  посторонний пользователь не видит строки во всех 9 таблицах; вставка от имени
  другого пользователя отклоняется. Анонимный SELECT и браузерный INSERT истории запрещены.
- После миграций Supabase больше не сообщает о пропущенных RLS-политиках,
  дублирующихся permissive-политиках, построчных вычислениях auth и отсутствующем FK-индексе.
- Начальный JS-пакет в сопоставимых локальных production-сборках: 510.98 → 417.81 КБ
  (−18.2%); gzip: 155.99 → около 125.06 КБ (−19.8%). Это размер передачи, а не
  измерение ускорения всех пользовательских действий.
- На ширине 390 px экран входа не создаёт горизонтальную прокрутку.
- Render за последний доступный час показывал около 78–80 МиБ памяти и низкую
  загрузку CPU; данных HTTP latency для достоверных p95/p99 не было.

## Оставшиеся ограничения

- Публичная демо-учётка сохранена по прямому указанию владельца. Любой посетитель
  может читать и менять её демонстрационные данные; реальные данные туда не помещать.
- Supabase сообщает `Leaked Password Protection Disabled`. Доступные инструменты
  не позволяют изменить конфигурацию Auth. Включите защиту в настройках Auth,
  если она доступна на тарифе: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection.
- Render использует бесплатный план. Холодный запуск после простоя остаётся
  ограничением хостинга; платный тариф автоматически не подключался.
- Supabase показывает информационные notices о пока неиспользованных индексах.
  При малом числе записей это не доказательство проблемы; полезные индексы не удалялись.
- Планировщик рассчитан на один процесс Render. Перед масштабированием на несколько
  процессов потребуется распределённая блокировка/очередь; доставка web push не даёт
  гарантии exactly-once. Без зарегистрированного устройства реальную доставку push
  подтвердить нельзя.
- Нагрузочное тестирование продакшена с большим потоком запросов не проводилось.
- Заглушки страниц «Календарь» и «Записи» остаются существующими заглушками;
  их продуктовые требования в этой задаче не определены.

Миграции применены к действующему проекту Supabase; настройки CORS и доверенного
прокси обновлены в Render. Заголовки Netlify поставляются вместе с публикацией клиента.
